# 设计 QA 报告 — TabMerge

比对基准：`docs/design/quiet-ledger.png`（ImageGen 产出的「静谧清单」视觉稿）
被测对象：`docs/images/popup-grouped.png`（真实 Chrome 渲染的扩展弹窗，400×600，同一状态：已按域名分组）

比对方式：两份图并排、在同一视口（400×600）与同一交互状态（已完成分组、8 个域名组、全部展开）下逐项核对。

> 操作区在比对后按用户反馈做了重构：视觉稿是「一条通栏主按钮 + 一行三个次级按钮」，实现改为 **2×2 等宽网格**（自动分组 / 解散分组 一行，收起分组 / 展开分组 一行），四个按钮成为同级操作，不再有 1+3 的割裂感。下方记录该次重构的处理与代价。

## 逐项核对

| 项 | 视觉稿 | 实现 | 结论 |
|---|---|---|---|
| 品牌行 | 左侧「TabMerge」15px 中粗，右侧灰字「37 个标签页」 | 同结构、同层级，数字随实际窗口变化；右端另加齿轮设置按钮 | 一致（齿轮为新增） |
| 主操作 | 墨绿实心按钮，层叠图标 + 分组文案 | 同色系、同图标（Tabler stack-2），位于 2×2 网格左上 | 一致 |
| 次级操作 | 三个纯文字按钮：收起(⌄)、展开(⌃)、解散(🗑) | 同样三个操作，改为带图标的等宽按钮格 | 一致（图标重做，见下） |
| 分隔线 | 一条发丝线 | 同 | 一致 |
| 清单行 | 6px 竖色条 + 域名 + 右对齐计数 + chevron | 同结构，色条为 Chrome 原生组色 | 一致 |

| 小节标题 | 稿面无「分组」标签 | 实现补了 | 见 P3-2 |

## 操作区重构（按用户反馈）

| 反馈 | 处理 |
|---|---|
| 按钮改名 | 自动分组 / 解散分组 / 收起分组 / 展开分组；manifest 命令描述与设置页标签同步改名 |
| 悬浮显示快捷键 | 每个按钮带 `data-tip`，弹窗打开时用 `chrome.commands.getAll()` 写入当前绑定；未绑定显示「未绑定快捷键」 |
| 图标风格统一 | 四个按钮统一用 Tabler 线性图标（24px / 2px 描边）：stack-2、arrows-split、fold-down、fold-up |
| 「解散」不要垃圾桶 | 垃圾桶易读成删除标签页，改用 `arrows-split`（一条线分成两支，语义为「拆开」） |
| 布局重新设计 | 由「通栏主按钮 + 三个次级按钮」改为 2×2 等宽网格；按反馈把「自动分组 / 解散分组」排一行、「收起分组 / 展开分组」排一行，每行一对相反操作 |
| 齿轮设置入口 | 头部右上角图标按钮，调 `chrome.runtime.openOptionsPage()` 直达设置页 |

### 代价与取舍

- 网格高度 92px（2×42 + 8 间距），比原「通栏 + 三个文字按钮」的 84px 高 8px。实测 8 个域名组仍能一屏看全（回归检查「8 个分组无需滚动即可看全」通过）。
- 快捷键提示的浮层位置按行自适应：第一行按钮的提示在下方（否则会压住品牌行），第二行按钮的提示在上方（否则会压住分组清单）。提示始终落在网格区域内，不遮挡弹窗的结构元素。
- 「自动分组」保留实心绿主按钮样式，与同行三个描边按钮形成主次；但四个按钮的几何形式完全一致，网格本身是均衡的。

## 问题与处理

### P0 / P1
无。

### P2-1（已修复）Windows 默认滚动条过重
首次渲染时清单区出现系统默认粗滚动条（12px 宽、灰底），与「静谧清单」的克制感冲突，且压住行内容。
处理：`.group-list` 改为 6px 细滚动条，`scrollbar-color` 与 `--hairline-strong` 对齐，轨道透明。

### P2-2（已修复）第 8 行被裁切
清单区写死 `max-height: 328px`，8 个分组时最后一行（linear.app）被切掉半行。
处理：改为弹性布局（`body` 限高 600px，清单 `flex: 1 1 auto; min-height: 0`），并收紧头部/分隔线/状态行的垂直节奏（合计让出 34px）。复测 8 个分组可完整显示且无滚动条，并加了回归检查「8 个分组无需滚动即可看全」。

### P3-1（接受）行高比稿面紧
稿面行高约 56px，实现为 44px。取舍：Chrome 弹窗最高 600px，44px 可让 8 个域名组一屏可见；56px 只能显示 5 组并强制滚动。紧凑清单更符合工具型弹窗的定位。

### P3-2（接受，刻意偏离）两处补充元素
- 清单上方补「分组」小节标签：清单同时包含扩展创建的组与用户手工建的组，需要一个归属提示。
- 底部补状态行：操作结果（分了几组、收起几个、解散几个）需要落点，稿面留白正好承担这个角色。

### P3-3（接受，刻意偏离）chevron 朝向
稿面所有行都是「>」。实现中展开态用「⌄」、折叠态用「>」，用箭头指示「点下去会发生什么」，比静态箭头更有操作提示性。

### P3-4（接受）弹窗容器由 Chrome 提供
稿面画了带圆角与投影的面板卡。真实扩展弹窗由 Chrome 渲染容器边框与圆角，扩展页面自身保持通栏，因此实现中没有面板圆角。

## 设置页重做

原设置页是单栏左对齐的文字流：页头、四个小节、若干段说明、两个表格和三行开关。每一块权重相同、纵向堆叠，扫读时找不到锚点——「太单调」的根因是缺少层级而不是缺少内容。

三版设计稿原稿（concept-1-ledger / concept-2-cards / concept-3-sidebar）已随仓库清理移除，方向决策记录如下：

| 稿 | 方向 | 结构 |
|---|---|---|
| concept-1-ledger | 双栏清单 | 纯白页，左名称右控件右对齐成一条竖轴 |
| concept-2-cards | 分区卡片 | 浅灰底 + 白卡片，每段一个带图标磁贴的卡头 |
| concept-3-sidebar | 侧栏控制台 | 左侧固定导航栏 + 右侧内容区 |

**最终采用方向 3 的骨架 + 方向 2 的卡片**：左侧 216px 固定导航栏（品牌锁套、四个分区、版本与隐私说明），右侧四张分区卡片，页面底色为浅灰、卡片为白。

### 逐项核对（实现 vs concept-3 + concept-2）

| 项 | 稿面 | 实现 | 结论 |
|---|---|---|---|
| 侧栏 | 216px 导航栏 + 品牌锁套 + 四项导航 + 底部版本说明 | 同结构，导航项带图标，当前项浅绿底 + 绿字 | 一致 |
| 卡片头 | 32px 浅绿图标磁贴 + 标题 + 说明 | 同，磁贴用 `--tile-bg` 浅绿 + 绿色图标 | 一致 |
| 快捷键 | 键帽（近黑小方块 + 等宽白字） | 同，用 `kbd.keycap`，mono 字体 | 一致 |
| 命令说明 | 稿面每行有副标题 | 实现补了五条说明（打开弹窗 / 自动分组 / 收起分组 / 展开分组 / 解散分组） | 超出稿面，改进 |
| 分段控件 | 深绿填充选中项 | 同 | 一致 |
| 页面底色 | 浅灰 + 白卡 | 同（`--page-bg` / `--card`） | 一致 |
| 窄窗 | 稿面未涉及 | 侧栏在 880px 以下收成 60px 图标条 | 补充 |

### 实现中修正的两个交互问题

- **侧栏高亮会跳过一节**：四张卡片高度不等（快捷键卡约 420px，分组名称卡约 200px），用「顶部越过分隔线即算当前」的规则会把「分组名称」整节跳过。改为「中心最接近视口中线的那一节算当前」，并对滚到底的情况单独兜底。
- **初始高亮算在内容渲染之前**：导航初始化时命令列表还是空的，卡片高度不对，导致首屏高亮停在错误分区。改为内容渲染完成后重算，并用 `ResizeObserver` 监听卡片尺寸变化（记住了新的分组名时会重新判定）。
